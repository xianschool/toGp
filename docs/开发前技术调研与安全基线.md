# 开发前技术调研与安全基线

> 历史调研记录：当前版本已经切换为六线谱专用 PDF-to-GP5 流程，并移除了 Audiveris、MusicXML 桥接和 Tesseract 资源。本文保留用于说明早期技术决策。

调研日期：2026-11-12

本文基于仓库中的《吉他谱识别与 GPX 生成网站开发计划.docx》整理。项目现已调整为供吉他爱好者小范围使用的本地工具，不以商业化为目标。网站和服务器部署不在本次范围内。

产品决策：

- MVP 只交付 alphaTab 生成的 `.gp`，面向 Guitar Pro 7/8。
- GPX 不纳入首版范围。
- 乐谱识别和文件处理只在用户电脑上完成，网站只提供静态介绍和下载，不接收用户文件。

## 结论

不要先搭建完整产品页面。首先验证一条最小闭环：

```text
PDF/图片 -> 用户本机 OMR -> MusicXML -> alphaTab Score -> GP -> 回读
```

首版不建设账号、数据库、任务队列、对象存储和公网文件接口。页面顺序先由用户手动调整，自动排序放到后续版本。

MVP 使用 alphaTab 直接写 `.gp`，不维护 GPX 适配器。Guitar Pro 6 及更早版本不在兼容范围内。

### GPX 技术背景

alphaTab 1.9.0 的 `Gp7Exporter` 明确写出 Guitar Pro 7+ 的 `.gp`，而 `GpxImporter` 只负责读取 GPX。ScoreTranslate 则是先调用 alphaTab 的 GP7 写出器，再转换其 GPIF XML、封装为 BCFS 并做 BCFZ 压缩，最终得到 GP6 的 `.gpx`。该路径仅作为技术调研记录，不进入 MVP。

ScoreTranslate 的 GPX 写出有三个已知边界：

- 每个内部文件约 3.85 MiB 上限，超过时明确拒绝。
- 多谱表会拆成独立音轨。
- GP7/8 音频伴奏、RSE 音色与部分轨内音色切换不会保留。

如果未来恢复 Guitar Pro 6 支持，GPX writer 必须作为独立适配器维护，不能让页面、Score IR 或 OMR 代码依赖其容器细节。

### GP 兼容性

`.gp` 是 Guitar Pro 7 引入的现代工程格式。Guitar Pro 7 和 8 使用 `.gp`，Guitar Pro 6 及更早版本不能读取。

alphaTab 的 `Gp7Exporter` 在容器内写入 `VERSION=7.0`，但当前 `GpifWriter` 同时写入 `GPVersion=8.1.3` 和 `EncodingDescription=GP8`。因此：

- 对 Guitar Pro 8 的兼容性最有把握，但仍需用真实桌面端打开、播放、保存和再次打开。
- GPIF 元数据带 GP8 标识，不能仅凭 `.gp` 扩展名或 `VERSION=7.0` 承诺 Guitar Pro 7 一定无警告打开。
- alphaTab 自身可以读取 GP3-GP8，但对 alphaTab 的回读通过只能证明格式可解析，不能替代 Guitar Pro 7/8 实机测试。
- 若产品明确承诺 Guitar Pro 7，应建立独立的 GP7 兼容档，并在发布前修正或验证 GP8 专用元数据和能力。

对本项目而言，`.gp` 是唯一首发输出格式，兼容路径比自制 GPX 更稳。Guitar Pro 6 及更早版本不在产品承诺范围内。

## 推荐开发基线

采用本地优先的轻量架构：

```text
静态网站
├── 产品介绍
└── 签名安装包下载

本地桌面应用（Tauri 2 + TypeScript + alphaTab）
├── 选择本机 PDF 或图片
├── 启动用户已安装的 Audiveris 进行识别
├── 导入 Audiveris 导出的 MusicXML
├── alphaTab 预览和必要校正
└── 导出 Guitar Pro 7/8 的 .gp
```

不建设公网处理 API。网站没有上传表单、账号、数据库、对象存储或文件下载代理，因此服务器不会接收用户乐谱，也没有用户文件生命周期和跨租户访问问题。

### Audiveris 使用方式

为降低许可证风险，本项目不修改、不打包、不再分发 Audiveris：

1. 用户自行从 Audiveris 官方发布页安装。
2. 首版由用户在 Audiveris 中完成扫描、识别和 MusicXML 导出。
3. 本工具导入 MusicXML，负责预览、校正和 `.gp` 导出。
4. 后续如增加自动化，只通过固定参数启动用户已安装的 Audiveris，不复制其源码、模型或安装包。

这是降低许可风险的工程方案，不构成法律意见。若未来要修改 Audiveris、将它打包进安装包并分发给朋友，需要按 AGPL-3.0 提供对应源码和许可信息。

### MVP 范围

- 只支持一次导入一份 MusicXML。
- 页面顺序在 Audiveris 中或导入前手动处理。
- alphaTab 用于谱面显示、播放、基础校正和 `.gp` 写出。
- 不实现自定义 Score IR、自动页面排序、账号、云同步、多人协作和遥测。
- 所有用户文件只保存在本机，任务完成后由应用清理临时文件。

如后续发现 Audiveris 手动步骤太重，再单独评估本地命令行联动，不改变“应用本身不打包 Audiveris”的边界。

## 本地安全边界

网站和桌面应用的风险已经分开处理。

网站侧：

- 只托管静态 HTML、脚本、图片和桌面安装包。
- 不提供文件上传接口，不保存用户数据。
- 不运行 OMR、PDF 渲染或其他昂贵任务。
- 安装包发布时提供 SHA-256 校验值。

桌面侧：

- 不信任导入的 MusicXML、图片和 PDF。
- PDF 和图片交给用户安装的 Audiveris 处理，应用不直接执行其中的主动内容。
- MusicXML 解析器禁用外部实体、网络访问和 DTD 加载。
- 启动外部程序时使用固定参数和绝对路径，不经过 shell，不拼接用户输入。
- 限制导入文件大小、页数和任务执行时间，避免误操作耗尽本机资源。
- 默认关闭遥测，不记录乐谱内容、文件名或本机路径。
- 只写入用户明确选择的结果路径，临时文件使用独立目录并及时清理。

## 首版验收

首版不追求完整产品，只验证实际是否好用：

1. 用户安装 Audiveris 后，能将一份吉他谱导出为 MusicXML。
2. 本工具能导入 MusicXML，保留音高、时值、调弦和 TAB 弦品。
3. alphaTab 能播放并进行必要修正。
4. 导出的 `.gp` 能被 Guitar Pro 8 打开、播放、保存并再次打开。
5. 整个流程不上传文件，网站服务器不接触乐谱。
6. 应用默认不发送遥测，临时文件可清理。

Guitar Pro 7 兼容性作为二次测试，不在首轮本机验证通过前扩大承诺。
